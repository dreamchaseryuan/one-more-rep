# Workout 内嵌所执行 ProgramDay 的完整快照

每个 Workout 把当时执行的 ProgramDay **整个抄一份**进自己：计划名、训练日名，
以及这一天规定的每个动作 `(exerciseId, 动作中文名, sets, repRange)`。
不是只存 `programId + programDayIndex` 让界面回头去查模板。

模板是可编辑的（明确需求），而且模板会随版本更新。如果历史只存引用，那么：

- 编辑某个训练日的动作 → 三个月前那条历史的「推日」指向了新的定义，当时的安排已经不对
- 改名或删除某个内置计划 → 相关历史标签变成「未知」，训练史静默地烂掉一半
- 动作从数据集中下架 → 历史查不到动作名，Deviation 显示成「某动作：计划 5 组，实际 3 组」，
  你知道少做了却不知道少做了什么

失败都是**静默的**：标签还在、还能点，只是内容是错的。这种错最难发现。

快照必须包含组数和次数区间，否则算不出 Deviation——只存名字的话，
「计划 5 组，实际 3 组」这句话就无从生成。动作中文名也一并抄进去，
让历史**完全自包含**：不依赖当前动作库、不依赖模板是否还在。

下标仍然保留，但只用于推导「下一个该练哪天」，不承担任何展示职责。

**代价**：Workout 和备份文件变大（每个动作约 30 字节，一次训练多几百字节，可忽略）；
结束训练时要把当时的计划安排一起写进去。备份格式升到 version 2。

## 推论：「下一个该练哪天」也必须按名字推导

快照里存了训练日名字，这顺带解决了一个否则会很难查的问题。

轮转如果按 `(上次的 programDayIndex + 1) % 训练日总数` 算，那么**插入或重排一个训练日**
会让所有历史记录的 index 语义整体偏移一位，轮转从此错乱——而且不报错，只是安静地让你练错日子。

所以推导要以**训练日名字**为准：按名字在当前计划里找回上次那天，取它的下一位。
只有名字找不到了（改名或删除）才退回按 index。

这也说明快照存名字不只是为了历史可读，**轮转的正确性本身依赖它**。

## 刻意不包含热身（2026-10-11 补）

训练日现在带一段热身清单，但**不抄进快照**。快照存在的理由是两件事：给记录标出「这是哪个训练日」，
以及算得出 Deviation。热身既不被记录（不产生 Set），也不参与 Deviation 的计算，
放进去就是让每一次训练记录都背上没有视图会读的数据。

这是有意的取舍，不是漏了。如果将来真要问「三个月前腿日的热身是什么」——那是个热身方案问题，
该去改计划，不是去翻历史。
