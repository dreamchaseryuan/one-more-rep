# 食物数据以「中国食物成分表」为种子，且不把它当主力

选 `Sanotsu/china-food-composition-data`（《中国食物成分表标准版第6版》）作为食物营养数据的种子：
1677 条、35 个营养字段、全部 per 100g。抽查鸡蛋 139 kcal/蛋白 13.1、全脂牛奶 65/3.3、
西兰花 27/3.5，与公开值一致。

**比较过的替代方案**：Open Food Facts（包装商品为主，中文覆盖零散、条目由用户众包，噪声大）、
USDA FoodData Central（英文美国食物，且需申请 key）、`LuckyHookin/foodwake`（1643 条，
但爬自第三方站点、2020 年后未更新、README 示例里就有数值缺失）。中国食物成分表是唯一权威的中文来源。

**四个必须记住的坑**：

1. 数据是**两个视觉模型从表格截图提取**、再由人工复核两个模型的分歧项。作者自己写明残留风险：
   「两个模型都识别错了，还错成一样」。所有数值都只能当参考值，必须允许使用者覆盖。
2. **没有声明 license**，底层书籍版权属北京大学医学出版社。自用可以，公开部署是灰色地带——
   比 Gym visual 那批媒体更严重，那批至少有书面转载许可。
3. **唯一的蛋白粉条目是错的**：`109007 蛋白粉（益力健乳铁乳清蛋白粉）` 蛋白仅 50%，
   而常规乳清是 70~80%。信它会让人每天少算约 40% 蛋白摄入——而蛋白是整个应用里唯一真正要盯的数字。
   这是数据**错配**（记录了某个具体商品）而非数据错误。
4. **生重/熟重不分**：`面条（生）301 kcal` vs `面条（富强粉，煮）107 kcal`，差 2.8 倍。
   必须强制区分，否则算出来的数字是假的。

**决定性结论**：拿真实场景实测（米饭 / 鸡腿 / 蛋白粉 / 食堂菜），**4 样里 0 样能直接用**——
米饭和鸡腿有数据但表达不了「一碗」「两个」「去皮」，蛋白粉那条是错的，食堂菜完全没有。
所以这张表**不是主力**，退居为两用：使用者建食物条目时提供参考值、想精确到克时提供食材数据。
主力是使用者自己拥有的 FoodEntry。

**原则**：预置**权威数据**（成分表条目），但**不预置我猜的数字**（份量、菜品配方）。
份量首次记录时问一次并给常见范围提示，记住即可。理由和蛋白粉那条教训一致——
一个错误的默认值会被反复使用且使用者未必发现，比没有默认值更糟。
